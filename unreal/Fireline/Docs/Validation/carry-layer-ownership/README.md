# M4 持枪层与下半身归属修正 — 2026-09-27

## 问题与证据

本轮范围是 M4 无移动输入→向前行走→停止，不是重做整套人物。诊断在同一次动画求值中记录 ground、mobility、upper action、BodyPose、ContactCarry 各阶段和最终渲染骨骼。现有 Contact 片段是既有改编资产，不是原始 donor；stage 6 不得称为原片直出。

ContactCarry 采样并混合整个人物，覆盖了 BodyPose 之前已经确定的 root、pelvis 和腿部。侧面行走约 0.95 秒，左脚在持枪层前后移位约 32 cm；三组全部下半身骨骼记录的最大覆盖距离为 111.839 cm。这解释了为何调整持枪会破坏原有起停步态，不能据此认定所有视觉缺陷都来自这一处。

## 修正

`FirelineCarryBaseStudy` 保留下半身求值结果，将完整躯干分支按现有局部连接偏移接回骨盆。双手与枪的共同锚点采用同一位移，不分别挪动手指或手掌；保持现有上身朝向，避免重复叠加骨盆朝向。既有定长肘部求解及上一轮右臂净空修正保留。

该开关已加入独立开发基线 baseline.json，启动器已重新安装并验证运行参数。未改 Ryan/DJ 绑定、蒙皮、模型或源动画；被拒绝的 CombatGround、SourceBody 等实验仍关闭。正式 0.1.10 和旧工程未覆盖。

## 实际验证

- UE 5.8 Mac Development Editor 构建成功。
- 三组同输入前后对照各 358 帧；持枪层下半身覆盖降至约 0.00001 cm（导出精度）。最终骨骼与渲染组件同精度一致。
- 双手与枪接触锚点误差与前臂求解长度误差记录为零；三组腕部约束最大值约 32.36°。这不等于表面无穿模。
- 24 组／2880 帧移动、反向、武器和离地回归；第一人称反馈在匹配帧上变化为零。
- 武器回归 33 项无失败，1341 个姿势样本无审计失败；该操作审计最大腕角为 41.391°，不声称所有动作均小于 35°。
- 检查正面、侧面、背面原生截图及起停关键帧，并启动实际开发版进入训练场检查第一人称。截图每秒 10 帧，不覆盖全部帧间运动。完整动作、体表碰撞和美术接受度仍需后续检查。

本机证据（不上传第三方图像／二进制）：Saved/CarryLoopBefore、CarryLoopCandidate、CarryBaseRegression 和 baseline-weapons.log。汇总见 comparison.json、regression.json。`scripts/analyze_carry_layers.py` 可重新分析这些追踪文件。
