## 实际发现

- Coyote已有模型和原生导轨/光学中心socket；使用M4 **实际SkeletalMesh RefSkeleton**安装，未另估计模型缩放/导轨。它在当前导轨上的光学中心，比机瞄轴局部上移约 **1.37cm**，不足以自动消除现有眼线差距。
- 19组原生序列中，静止/水平/完全Aiming子集的虚拟眼点到瞄准轴误差：机瞄约14.02–17.50cm，Coyote约12.45–16.12cm。这是诊断代理值，姿态/转向子集不同，**不是配对A/B美术改善量**。四面近景仍明显看出瞄准线低于眼区。
- 旧 `stock_hold_cm` 偏向底垫上缘。对后向法线、中心Y<7cm的一组34个实际面做面积加权，中心比旧点低约4.15cm。该筛选帮助定位旧点问题，**没有据此直接抬枪或宣布肩窝已匹配**。
- 从现存成熟源FBX读取的Head主导表面，原始包围尺寸约18.02×24.25×26.81cm；当前头盔约27.97×32.72×28.90cm。高度并非简单“太大”的主因；宽度、下颌和颈部连接需结合完整姿态处理。原始单位/比例不同，不直接全局缩放头部，也不修改绑定。

## 验证范围

原生UE5.8构建成功。30Hz，19组原有方向、起停、瞄准、快速打断、俯仰和转向序列，2311个采样、38张Metal截图；逐帧安装/选择可见性检查零错误，最大相对安装平移1e-9cm，稳定相对转角为0。机瞄/Coyote两种状态都覆盖。四面近景逐张查看、完整序列总览查看；不是所有部位/动作的视觉验收。

与2026-09-29恢复版短序列对照19781条骨骼行：最大单轴位置差0.000180cm，四元数分量差约1.02e-6，缩放差0。源码没有更改Retarget/Aim/Input/身体注册；这些小差异属于原生求值浮点变化。1252份原始资源哈希检查零变化。

最终UI修订只加入Z近景切换和明确未完成提示，又做一次原生四面短检查；完整19组安装检查是在相同安装/姿态代码上完成的。没有重做3种采样率的全套身体几何审计。5参照的实体键盘交互、真实鼠标延迟没有自动测试；原生序列是脚本控制，不能冒充实体交互验收。前两次短截图有引擎准备shader的提示；最终UI侧面截图中提示已消失，瞄具呈现原生深色材质。本轮没有独立审计所有材质预热。

初次观察检查因 `acos(dot)` 放大接近单位四元数的舍入而误报约0.0067°安装误差，改用归一化相对四元数的 `atan2` 后复核。初次失败截图/日志保留，未覆盖。

## 后续决定

头盔/颈部外形范围仍待用户选择：建议保留Ryan科幻风，按成熟参考局部整理头盔下缘、下颌和颈部，然后建立真正无相交的单帧贴腮/肩窝接触；若必须完全保留外形，则继续研究适合当前壳体的整身姿态，不能保证已有方案可行。

只有单帧实际表面、固定骨长、腕肘关系、双手握持和四面观感通过，才能继续动态抬枪/移动，再进入换弹。不得因为这个观察入口和安装检查通过而宣称第3阶段完成。
