# M4 多方向走跑候选（2026-09-27）

按 NEXT_DEVELOPMENT 第2阶段推进的独立原生测试。不是默认游戏更新，也不是所有动作的视觉验收。当前 Ryan/DJ 比例派生模型、原手形和选定 TastyTony/Pichuliru M4 保留；没有修改模型、绑定、权重或原始动画。

## 体验入口

Finder 桌面「火力对决／**测试版·M4多方向走跑.app**」，双击打开。

- WASD：以当前人物观察朝向为基准，前后左右及组合斜向移动。
- Shift：慢跑；松开恢复步行。这里没有接入冲刺、蹲跳、滑铲或射击。
- Q/E：改变观察朝向；站定后由源图触发原地转身，移动中按其原生朝向逻辑转向。
- 鼠标：只环绕观察镜头；1/2/3/4：当前人物的正面/右侧/背面/左侧。
- R：回到测试起点；不是恢复所有动画状态。

先试侧移、后退和斜走，再按住Shift走跑切换、松键急停和左右反向，最后站定用Q/E转身，松键后观察完整转身收尾。入口与正式0.1.10、原先前向起停入口同目录。前向入口继续只使用Stage1路径；两个入口共享可变的本地研究模块，不应当称为冻结版本。

## 实现与来源

源为已经下载的 Sixze ALS-Refactored `b754d6f0f2bb03741d301f8fb88077ebfe561e17`。保留原 Rifle 完整图、四向混合及斜向组合、相位、方向阈值、速度相关朝向和转身曲线；没有通过单独旋转腰部制作横向动作，也没有另外创造交叉步动画。

实际输入和位移仍由一个 Fireline CharacterMovement 执行。隐藏的ALS角色关闭物理与自动tick，接收真实速度、加速度、位置、观察朝向和步态，再手动执行其完整Character/Anim更新。原图的方向性Actor旋转同步给整个目标角色。源步行175、跑375 cm/s按当前腿长比例1.151227224换算，测试速度约201/432 cm/s；没有改变默认训练场的速度。

Source Movement的物理tick停用后，额外复现其GaitAmount速度区间映射供原生旋转速度使用。隐藏网格被逐帧主动评估，桥接代码必须让ALS识别它正在更新：在其Tick前置瞬态bRecentlyRendered，防止NullRHI里RefreshMeshProperties反复MarkPendingUpdate而清空脚锁；不修改源类默认对象或uasset。

双手/手指/所有M4零件仍为同一接触组合。步行保留原校准；跑姿新增单个固定胸腔空间注册，数值见 jog-fit.json。注册以原持枪层**实际经过插值的跑姿权重**混合，包含停跑尾段，不以Shift按钮或原始PoseGait直接切换。原图Relaxed/TwoWayBlend_4在编译类中成为AnimGraphNode_TwoWayBlend_1；代码核对插值配置及输入等于PoseState.GaitRunningAmount，缺失或不符即失败，不猜测替代节点。原源图配置摘录见 source-blend-node.txt。

靴底使用现有实际混合权重表面求解。在腿接近完全伸直时，用精确可达距离补偿整个骨盆/身体高度，再放置双脚；固定骨长、保留源脚踝横向路径，不移动膝盖枢轴或拉伸骨头。跑步的腾空相位允许双脚同时离地；只有源接触曲线完整落脚时才检查贴地，不能强压一只腾空脚。

## 发现并纠正的问题

1. 初始纯前向校准直接用于慢跑，枪托和前臂穿入胸部；实际皮肤/枪械顶点及三角形检测发现，初版不合格，保留 initial-failed-summary.json。
2. 只用PoseGait驱动跑姿注册过早退回步行。原Rifle图实际有下降速度5的独立插值，停跑时两者不同步；保留 curve-weight-failed-summary.json。改为读取运行中真实节点权重，并以完整武器表面重新注册。
3. 初始转身用例只留2.4秒，180度观察方向变化已占1.5秒，尚未等过激活延时和转身收尾。原生逻辑不改，用例延长到4.8秒；不能将过短测试窗口误判为没有180度动画。
4. 30Hz侧跑两帧源脚踝目标超出当前腿长约0.41/0.19cm。新全身可达性补偿保持原脚踝横向位置，消除失败时冻结上一帧的风险。60Hz成功不能代替此检查。
5. 一次后台空编辑器触发热重载，生成的后缀库与启动清单不一致。后续构建使用NoHotReloadFromIDE并核对实际模块清单，再重跑最终验证；早期运行不作为最终证据。

## 重现

`python3 scripts/prepare_live_carry_study.py --build --install --directional` 构建并安装独立入口。原引擎启动参数增加 `-LiveCarryDirectional -LiveCarryAudit -StudyFPS=60` 可运行24组检查；30/120改变StudyFPS。实际运行输出在LiveCarryProject/Saved/LiveDirectional。

`audit_live_carry.py --directional --fps 60` 读取原生最终姿态做表面检查；`measure_directional_source.py --fps 60` 对照同次源输出。`--sample-step`只用于定位，不能用于最终验收。重新注册时先使用 `-LiveDirectionalCalibrate` 捕获未加跑姿注册的数据，保存到calibration-60，再执行calibrate_directional_carry.py；不能对已修正姿态重复拟合并叠加注册。

公开仓库不包含第三方网格/动画二进制；原始726个ALS文件与1252个Fireline资源均需独立校验。没有新增下载、付费服务或子智能体。
